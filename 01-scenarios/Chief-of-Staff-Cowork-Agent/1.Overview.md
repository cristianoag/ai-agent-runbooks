# Chief of Staff Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Leadership productivity and executive readiness  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Cowork, Outlook, Teams, calendars, SharePoint, OneDrive, accessible task sources  
**Complexity:** Intermediate; configuration-first, with significant governance and validation  
**Status:** Documentation available; tenant readiness and pilot acceptance required

A leader's weekly picture is scattered across mail, meeting recaps, conversations, files, and
tasks. This scenario assembles that context into a source-backed view of priorities, decisions,
risks, asks, and follow-ups. Cowork prepares leadership briefs, drafts stakeholder updates,
builds leadership review packs, and highlights visible team work and blockers.

The audience is leaders, managers, executive assistants, and Chief of Staff delegates.
An assistant's role does not grant access to a leader's mailbox or private context: validate
the signed-in user's actual permissions and supported retrieval surfaces.

This is **review-ready preparation, not an autonomous executive or an employee assessment tool**.

---

## Business Outcomes and Baseline

| Current problem | Intended improvement | Measure before and during pilot |
|---|---|---|
| Rebuilding the weekly picture manually | Faster first priority decision | Brief preparation minutes and decision latency |
| Rewriting updates from scattered threads | Consistent, sourced executive drafts | Drafting plus review time; corrections per draft |
| Assembling board/steering material repeatedly | Reusable leadership-pack structure | Pack preparation time and source completeness |
| Discovering commitments late | Earlier visibility of documented risks and asks | Missed commitments and approval-queue latency |
| Chasing status from direct reports | A factual visible-work digest | Follow-up effort and useful blocker identification |

Measure review effort and usage costs as well as generation time. Training examples are not
evidence of a customer's realised savings. Set the pilot's improvement target with its sponsor.

## Five-Skill Scope

| Skill | Responsibility | Required output |
|---|---|---|
| `leader-concierge` | Select one appropriate workflow; clarify ambiguous intent | Skill name, reason, trigger phrase, confirmed audience/period; no content production |
| `leader-360` | Prepare the weekly leadership view | Upcoming-week dashboard, results-focused leadership update, risk lens, prioritised first moves, sources and gaps |
| `executive-drafts` | Prepare one executive communication | Point-first draft, evidence where useful, explicit ask; email, Teams update, note, or delegation message |
| `leadership-pack` | Assemble board, steering, QBR, or operating-review material | Narrative, decision log, risk table, action register, key metrics, source list and gaps; Word brief or PowerPoint-ready outline |
| `team-pulse` | Summarise direct reports' visible work | Sourced completed work, meetings led, collaborators, blockers, follow-ups, and visibility gaps; no employee evaluation |

The default rhythm is `leader-360` on Monday at 08:00 in an agreed local timezone, with the
other skills on demand. Start on demand; enable recurrence only after quality and approval
tests pass. A schedule prepares a draft, not permission to distribute it.

## Scope Boundaries

**Base delivery:** configure the five existing skill definitions, reference rules, routing,
source boundaries, output sections, and an agreed pilot audience. Existing Microsoft 365
sources remain authoritative; no new index, model, custom code, or connector is required.

**Separate work:** third-party/on-premises integrations, permission/content remediation,
custom UI, new skill families, additional languages, brand-system creation, and broad rollout.
Optional Power BI evidence requires its own approved source-access path; it is not a base
Chief of Staff prerequisite. Do not silently expand into background surveillance or alerting.

The [resource guide](0.Resources/README.md) includes the published Cowork plugin and skills-only
archives, their contents and the communications-skill naming difference between variants.
Select and approve a package, resolve any routing differences, and validate it in the target
tenant before setup is accepted.

## Safety and Governance

- Use only agreed sources the signed-in user can access; show missing evidence instead of
  inventing a name, owner, due date, quotation, decision, or metric.
- Distinguish recorded facts from proposed priorities. RAG status follows agreed evidence
  rules; insufficient evidence is **unknown**, not green.
- Private calendar, mailbox, travel, personal, and restricted meeting details are not
  automatically suitable for an outbound leadership pack.
- `team-pulse` must not rank, rate, score, compare employees, infer sentiment/wellbeing,
  analyse working hours, or infer performance from message volume or absence of evidence.
- Draft first. Require explicit review of content, recipients, destination, and permissions
  before sending, posting, sharing, filing, changing calendars, or creating/changing schedules.
- Instructions alone are not an authorization boundary. Verify the actual runtime controls;
  retain manual-only actions where mandatory approval cannot be demonstrated.
- Use existing sensitivity, retention, and audit controls. "No new index" does not mean no
  processing, generated files, or conversation retention.
