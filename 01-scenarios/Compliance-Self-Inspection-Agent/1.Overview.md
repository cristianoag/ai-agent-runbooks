# Compliance Self-Inspection Agent — Overview

## Scenario Overview

| Property | Value |
|----------|-------|
| **Scenario Type** | Compliance Risk Awareness / Employee Self-Inspection |
| **Agent Type** | Interactive (user-initiated, self-service) |
| **Primary Tools** | Microsoft Copilot Studio, Power Automate, Dataverse (Prompt tool), OneDrive for Business, Outlook, SharePoint, Excel Online, Power Platform admin center |
| **LLM** | GPT-4.1 (Copilot Studio prompt tool) |
| **Complexity** | Intermediate |
| **Status** | Draft |

This scenario describes how to design, build, and operationalize a **Compliance Self-Inspection Agent** — an employee-triggered Copilot Studio agent that scans an individual's own OneDrive documents and Outlook mail, detects language that may warrant attention from a **fair-trade / antitrust compliance** perspective, and returns a personal risk-rated result sheet.

The agent is deliberately designed as an **awareness tool, not an enforcement tool**. It surfaces findings to the individual employee; the interpretation of those findings and any follow-up action remain entirely with the employee, supported by the Legal team.

---

## Problem Statement

Employees routinely author and receive documents and emails that contain language which, from a fair-trade / antitrust standpoint, deserves a second look — pricing or volume discussions, competitor information exchange, trading-condition negotiations, or market-allocation language. In most cases this is not intentional misconduct; it stems from a simple lack of awareness, compounded by the absence of any mechanism that lets an employee check their own content before it becomes an issue.

### Current Challenges

| Area | Current State | Problem |
|---|---|---|
| **Inspection tooling** | General-purpose assistants and search | Index-based retrieval misses files; coverage cannot be evidenced, so inspection results are not trusted |
| **Inspection method** | Manual, ad-hoc keyword search by each individual | Keyword choice and scope are subjective and inconsistent; the exercise is time-consuming |
| **Inspection cadence** | Irregular / on demand | No systematic record that a self-inspection was ever performed |
| **Awareness level** | Varies by individual | Compliance sensitivity differs widely across the organization |
| **Privacy expectation** | Legal review of individual content | Employees resist any model where a central team reads their documents |

---

## Solution Summary

A Copilot Studio agent that each employee runs **on their own account**. When invoked, the agent:

1. Asks the employee for a **start and end date**, and validates that the window falls within the configured limit (default: 1–120 days; the ceiling can be raised if the organization needs a longer look-back).
2. Enumerates the employee's own OneDrive documents and Outlook messages (including attachments) for that window, through Power Automate flows running under **the employee's own credentials**.
3. Extracts text and passes it to a centrally governed **prompt tool** that holds the Legal team's keyword taxonomy and returns per-keyword match counts by category and severity.
4. Applies a **deterministic scoring formula** — maintained in an Excel template owned by Legal — to convert those counts into a High / Medium / Low attention level per item.
5. Writes a personal result sheet to the employee's own storage and emails them a completion notice.
6. Records only **execution metadata** (who ran it, when, scope, counts) into a Legal-owned SharePoint workbook — never document content.

The separation is the core of the design: **content stays with the individual; only completion evidence reaches Legal.**

## How It Works

```text
[Employee]  Starts the agent (voluntary, self-service)
     ↓
[Scope]     Selects a start and end date
            └─ validated against the scan-window limit (default max. 120 days, adjustable)
     ↓
[Agent]     Full scan of the employee's own workspace for that window
            ├─ OneDrive documents (Word, Excel, PowerPoint, PDF)
            └─ Outlook mail (message body + attachments)
     ↓
[Keyword Matching]   Legal-defined keyword taxonomy applied
                     (categories × High / Medium / Low severity)
     ↓
[Risk Scoring]       Weighted score → attention level (High / Medium / Low)
     ↓
[Result Sheet]       Per-item list with matched keywords and reason summary
     ↓
[Employee Review]    Employee reads findings → consults Legal if needed
     ↓
[Execution Log]      Self-inspection completion record stored for Legal
```

### Attention Levels

| Level | Meaning |
|---|---|
| 🔴 **High** | Content should be reviewed from a fair-trade perspective; consulting Legal is strongly recommended |
| 🟡 **Medium** | Context should be confirmed; consult Legal after self-review if concerns remain |
| 🟢 **Low** | Keywords present, but substantive attention is unlikely to be required |

### Scoring Logic (default)

| Element | Rule |
|---|---|
| Score formula | `item score = Σ (weight of each matched keyword)` |
| Weights | High-risk keyword = 3 · Medium-risk = 2 · Low-risk = 1 |
| Banding | Low = 1–3 · Medium = 4–7 · High = 8 or above |
| Escalation rule | If two or more **distinct categories** match simultaneously, raise one level |
| Exception rule | If **any** high-risk (3-point) keyword is present, the item is at least **Medium** |

The formula lives in a single cell of the Legal-owned Excel template, so the rubric can be re-tuned without touching the agent, the flows, or the prompt.

## Differentiation vs. a General-Purpose Assistant

| Aspect | General-purpose assistant | Compliance Self-Inspection Agent |
|---|---|---|
| Scan coverage | Index-based; items can be missed | Enumerates the user's own OneDrive and mailbox directly through connectors |
| Keyword scheme | Whatever the user happens to type | Centrally curated and versioned by Legal |
| Attention rating | None | Deterministic High / Medium / Low classification |
| Inspection record | None | Automatic execution log and organization-wide completion tracking |
| Purpose | General productivity | Purpose-built to raise fair-trade compliance awareness |

## Business Outcomes

| Outcome | Description |
|---|---|
| 🎯 Raised compliance awareness | Employees see, in their own content, the language that draws regulatory attention — the single most effective awareness intervention |
| 🧾 Demonstrable self-inspection evidence | Every run is logged, giving Legal defensible evidence that a periodic self-inspection program is operating |
| 🔐 Privacy-preserving by design | Employees inspect only their own content; Legal sees completion statistics, never document contents |
| ⚖️ Consistent inspection standard | A single, centrally governed keyword taxonomy replaces subjective per-person keyword guessing |
| ⚡ Reduced Legal workload | Low-value "is this okay?" traffic is filtered by self-triage; Legal engages only where the rating warrants it |
| 🛠️ Low-code maintainability | Keywords, scoring bands, scan-window limit, result layout, and notification wording are all editable without code |
| 📈 Extensible to other domains | The same pattern applies to export control, anti-bribery, insider trading, and confidential-information handling |

## Target Users

| User Group | Description |
|---|---|
| 👤 **Employees (primary users)** | Run the agent on their own workspace, review the result sheet, and decide on follow-up |
| ⚖️ **Legal / Compliance team** | Own the keyword taxonomy and scoring rubric; monitor organization-wide completion; answer escalated questions |
| 🛡️ **IT / Information Security** | Own environment security groups, DLP policy, custom Dataverse security roles (including the `AI Event` restriction and the Delegate role), run-history retention settings, audit-log retention, and app deployment |
| 🧑‍🔧 **Agent makers / Power Platform admins** | Maintain the agent, flows, prompt tool, prompt-tool sharing, connection modes, and solution lifecycle across environments |
| 📊 **Compliance program owners** | Use completion statistics to plan campaigns and report to management; own the launch communication, usage guidance, and campaign cadence |
| 🎓 **Adoption / change management owners** | Prepare the announcement, the "how to run your self-inspection" guide (including the one-time connector consent prompt and expected run duration), and the help path for employees who get stuck |

## ✅ In Scope

- Employee-initiated scanning of the employee's **own** OneDrive documents and Outlook mail (body and attachments), bounded by a user-selected date range within a configurable limit (default 120 days, extendable to fit the organization's inspection cycle).
- Text extraction from `.docx`, `.xlsx`, `.pptx`, and `.pdf`, plus email body text.
- Centrally governed keyword taxonomy organized by category and severity, maintained by Legal in a Copilot Studio prompt tool.
- Deterministic weighted scoring with escalation and exception rules, maintained in an Excel template.
- Personal result sheet delivered to the employee's own storage plus a completion email.
- Execution-history logging (who, when, scope, item counts) to a Legal-owned SharePoint workbook.
- Environment strategy, credential strategy, sensitive-data exposure controls, and phased rollout guidance.
- Production-cutover configuration split between IT admin (environment-scoped custom security roles, Delegate role, run-history retention) and agent maker (prompt-tool sharing, connection modes, flow clean-up).
- Adoption and change management: sizing the scan window against the Power Platform capacity the organization's licenses actually grant, and providing employees with usage guidance before rollout.

## ❌ Out of Scope

- **OCR** — text rendered inside images (scanned pages, screenshots, picture-embedded text) is not read.
- **Legal advice** — the agent classifies and displays; it does not interpret, advise, or determine liability.
- **Scanning other people's content** — no administrator or Legal user can run a scan against another employee's workspace.
- **Blocking or remediating content** — the agent never deletes, quarantines, or modifies documents or mail.
- **Real-time / always-on monitoring** — inspection is a discrete, user-triggered run, not continuous surveillance.
- **Sources outside OneDrive and Outlook** — Teams messages, on-premises file shares, and third-party repositories are not scanned in this baseline.
- **Unbounded historical scanning** — a single run covers only the selected window, up to the configured limit.

## Key Design Decisions

| Decision | Rationale |
|---|---|
| **User-initiated only** | Preserves the "self-inspection" framing and avoids the surveillance perception that would kill adoption |
| **End-user credentials for user-data connectors** | Guarantees an employee can only reach their own data, and distributes API throughput limits across users instead of concentrating them on one maker account |
| **Maker credentials for the Legal-owned template and history workbook** | Employees must be able to write completion evidence without being granted access to the Legal storage location |
| **Deterministic scoring outside the model** | The attention rating must be explainable and auditable; the model counts, the spreadsheet decides |
| **Results delivered to a file and by email, not in chat** | Keeps document content out of the conversation transcript store, which materially narrows the sensitive-data footprint |
| **Bounded scan window (default 120 days)** | Caps run duration, connector API volume, and throttling risk, and keeps each run proportionate to the awareness purpose. The ceiling is a setting, not a hard constraint — it can be raised moderately (e.g. to a half-year inspection cycle) after measuring run time in the development environment and confirming the licensed Power Platform capacity supports it (see [Architecture §6](2.Architecture.md#6-capacity-licensing-and-adoption)) |
| **Scan window sized to licensed capacity** | Every scanned item consumes Power Platform requests and connector calls that are metered per user per day. The window is therefore a licensing decision as much as a compliance one, and must be validated against the entitlements the organization actually holds (Microsoft 365 seeded rights vs. Power Automate Premium) |
| **Guided rollout rather than silent deployment** | Because the run is voluntary and the first launch shows an unfamiliar connector-consent prompt, adoption depends on employees receiving usage guidance up front; without it, completion rates stay low and the Legal evidence trail is incomplete |
| **Prompt input/output not retained** | Custom security roles deny writes to the Dataverse `AI Event` table and cloud flow run-history retention is switched off, so scanned text is not persisted anywhere for later reading |
| **Flows wired as topic nodes, not agent tools** | Orchestration stays deterministic instead of model-selected, and credentials are configured in one place (connection references) |
| **Single production environment** | Enables one-shot deployment, unified auditing, and organization-wide completion tracking |
| **Split cutover ownership (IT admin ↔ maker)** | Environment-level permissions and retention settings need Power Platform admin rights, while flow and prompt changes belong to the maker; sequencing admin work first avoids permission-error rework |
